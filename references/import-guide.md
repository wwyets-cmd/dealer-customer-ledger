# 每周订单数据导入教程（回单记录）

> 代理商每周把销售/订单明细导入一次，代理自动分析识别后写入「回单记录」表。一次导入几十到几百行都适用。

## 一、数据格式要求（导出信息必须包含）

每周导出的 Excel 销售数据至少包含以下信息（列名可有别名，代理自动识别）：

| 必需字段 | 常见列名别名 |
|---|---|
| 订单日期 | 订单日期 / 日期 / 下单日期 / 发货日期 / 开票日期 |
| 客户名 | 客户 / 客户名称 / 客户公司 / 经销商 / 收货单位 |
| 产品 | 产品 / 品名 / 货品 / 规格 / 型号 / 商品名称 |
| 数量 | 数量 / 件数 / 出货数 / 采购量 |
| 单价 | 单价 / 单价（元）/ 售价 / 成交价 |
| 总金额 | 总金额 / 金额 / 销售额 / 总价 / 含税金额 |

可选字段：业务员 / 销售员 / 业务、订单号 / 单号、备注。

## 二、导入识别规则（自动执行）

1. **读取文件**：用户发 Excel（.xls/.xlsx）、CSV 或表格截图，逐行解析；截图先读图再结构化。
2. **表头别名识别**：按上表把各列映射到回单记录字段（订单日期/客户名称/产品/数量/单价（元）/总金额（元））。
3. **产品归一**：产品名按 references/vocab-errors.md 词库归一到炬森产品分类（升降机/衣帽间五金/拉篮/水槽/铰链/滑轨/反弹器/辅料等）；识别不出或拿不准的先问，不要乱写。
4. **客户匹配**：按客户名查「客户名单」，存在→写入「关联客户」；不存在→先建档（客户性质=存量客户，负责业务员=匹配到的业务员或录入人）再挂关联。
5. **业务员**：Excel 有业务员列→直接用；没有→按客户名单「负责业务员」自动匹配。
6. **数字回读复核**：数量、单价、总金额为关键数字，写入前逐项回读确认（识别/听写易错）。

## 三、写入流程

- 用 `lark-cli base +record-batch-create --table-id <回单记录id>` 批量写入；create_records 为字段 map 数组。
- datetime 写 `YYYY-MM-DD HH:mm:ss`；number 写数字；link 写 `[{"id":"<客户记录id>"}]`。
- 只写存储字段；auto_number / formula / created_at 等只读字段不写。

## 四、导入后校验（必须）

1. `+record-list` 回读本批记录，核对条数与 Excel 行数一致。
2. 汇总校验：总金额（元）合计 ≈ Excel 合计（差值>1 元必须查明原因）。
3. 向使用者回执：导入 N 条、涉及 M 个客户、总金额合计、无法识别的行（如产品名存疑、客户未匹配）。

## 五、常见问题

- **客户名不一致**：同一客户在 Excel 与客户名单名称不同（如简称/全称）→ 先查证确认，不自动建重复客户。
- **产品不在词库**：先问使用者归类到哪个品类，确认后再写入；不猜测。
- **单价/金额不一致**：总金额与数量×单价差异大（优惠/运费）→ 以 Excel 实际总金额为准并备注。
