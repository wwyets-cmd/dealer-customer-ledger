# 代理商客户台账录入（WorkBuddy 版）

把使用者的口头信息（含语音转写、照片）自动写入飞书多维表格，5 表联动，一次语音可录多表。

> **与豆包版的唯一差异在工具层**：本版不使用 `lark-cli`，所有飞书多维表格读写、附件上传都通过 WorkBuddy 已配置的**「飞书」连接器（MCP）**完成；业务规则（一人一档、字段映射、口音纠错、上样水印、工作群汇报、每周导入）与豆包版完全一致。

## 安装（首次使用必须前置确认）

1. **确认录入人（多代理商，不预置名单）**：技能会被多个代理商团队使用，不内置业务员名单。安装/首次使用时询问录入人/业务员的**正式全名**（不要"王经理/老王"称呼）；同一人换设备/换对话安装须用同一个名字，避免看板把一人拆成多人。姓名在对话内记住，之后自动填入「负责业务员/拜访业务员/业务员」。
2. **配置飞书连接器**：在 WorkBuddy 左侧「专家·技能·连接器」→「连接器」→ 添加「飞书」，按指南完成授权（绑定飞书开放平台应用，开通多维表格 Base 的读写与记录创建权限）。**完整步骤见 references/install-workbuddy.md**。未配置连接器前无法写入。
3. **确认 Base（代理商自行复制模板）**：每位代理商复制一份模板得到自己的表，录进自己副本。模板 `https://my.feishu.cn/base/FyKib8lh8aIqJxsHppUcVkDnnEb`（5 表齐全、无示例数据）。复制教程见 references/install-workbuddy.md。不要在模板母版上录数据。
4. **结构对账 / 自动升级（旧副本兼容）**：确认 Base 后、建个人视图前，通过飞书连接器按 references/base-schema.md 末尾「结构对账与自动升级」对该副本对账：拉取实际表/字段/视图/看板组件，与最新结构比对，**缺什么补什么（只增不删、不动已有数据，含数据列先读值再安全转换）**，串行间隔 2–3 秒防限流，完成后回执补了哪些。**技能每次更新版本后、首次录入前会再自动对账一次**，旧表无需重新复制。
5. **为录入人创建个人视图（数据全员可见、不做权限隔离）**：本台账不配高级权限、不做行级保密，所有业务员可见全团队客户/拜访/回单，主管看数据看板汇总（用户确认 C）。确认 Base 与录入人姓名后，通过飞书连接器检查是否已有以下 3 个以本录入人命名的视图，缺哪个就在对应表新建 grid 视图并按业务员字段精确筛选＝录入人姓名：①客户名单「〈姓名〉的客户」（负责业务员=姓名）；②拜访记录「〈姓名〉的拜访」（拜访业务员=姓名）；③回单记录「〈姓名〉的回单」（业务员=姓名）。已存在跳过；新同事首次安装自动补建。
6. 确认后展示录入模板（references/entry-template.md，含口语示例），开始录入。

## 核心工作流

1. 解析语音/表格 → 按 references/entry-template.md 的板块（客户/拜访/竞品/回单/上样）归类；信息越详细越好。
2. 词库匹配（内部处理，不展示纠错清单）：按 references/vocab-errors.md 归一（东泰=DTC、脚链→铰链、智能收纳舱→升降机），拿不准复述确认。**客户提到的意向产品，按 references/product-catalog.md（276 个型号系列）归一到规范系列/型号名**：能对上型号写"业务大类+规范系列"（如升降机-星移SL-S、拉篮-天蝎N810），只说大类就记大类并保留原话，尺寸/颜色/弯别作规格补充。
3. 客户存在性（**一人一档，禁止重复建档**；不预置存量，边录边建）：通过飞书连接器拉取客户名单，按**名称归一化 + 字号模糊匹配**查重。
   - **归一化**：去掉行政区划（省/市/区县/县）、组织与行业后缀（有限公司、有限责任公司、股份、集团、商贸、贸易、装饰、装饰材料、建材、五金、全屋定制、家居、家具、工厂、厂、门店、经营部、经销处等）、空格标点，得到**核心字号**（如"济南华鑫全屋定制"→"华鑫"、"德州贝壳定制"→"贝壳"）。
   - **匹配**：核心字号完全相同或互相包含即候选；字号短于 2 字不做包含匹配（防误并）；**跨城市同名默认不同客户，需确认**。
   - **结果处理**：唯一命中→判同一家，挂接并补全，回执注明"匹配到已有客户 XX"；多个候选→列出（全称+城市+联系人）让使用者选定，**不擅自合并**；无命中→确认为新客户再建档。
   - **字号不同但实为同一家**（曾用名/改名，如"青岛炬鑫=青岛博丽特"）：匹配不到，**只有使用者明确说明才按同一家处理**，以其确认的规范全称为准。
   - **已存在**：在原客户记录上**补全/更新**（电话、地址、卡点、开发阶段、跟进日期等），**绝不新建第二条**；本次拜访、竞品、回单、上样都挂到同一条客户；**不得因本次拜访人不同而改动「负责业务员」**。
   - **不存在**：先在客户名单建档（「负责业务员」=本次录入人，即首建人），再挂本次关联。**若为新开发客户（客户性质=新开客户或使用者明说"新开发/新开拓"）：勾选「是否新开拓」=true、填「新开拓日期」=今天；该勾选永久保留，后续上样/首单/阶段流转/改存量都不得取消。** 老客户不勾。
   - **负责业务员归属（默认首建人固定，可手动转交）**：客户建档后负责业务员固定为首建人；其他业务员再拜访时，拜访记录如实记实际拜访人，但客户名单负责业务员**不变**。仅当使用者明确说"把 XX 客户转给 XX"时才更新负责业务员，并回读确认。
   - 每次拜访本身记录到「拜访记录」（可多条）；拜访次数、频率、最近拜访日期、整体回单金额等由表内公式随关联自动更新，无需手改。
4. 自动补全：拜访日期=今天、业务员=录入人、上样日期=照片水印时间（见下）。
5. **写入前必填校验**：按 references/entry-template.md「必填字段规则」逐项核对——客户名称、客户性质、客户类型、详细地址、本次目的/对接内容、竞品信息、当前卡点、下一步动作+下次跟进日期为必填；缺失项**一次性集中追问**补齐才提交，不替客户默认或编造；竞品真无→"无竞品/客户未透露"、卡点真无→"无卡点/正常推进"，不留空；联系人、电话可"后补"。
6. 写入：通过飞书连接器的多维表格记录新建/更新工具写入（字段映射见 references/base-schema.md；select 单选写选项名、多选写数组（竞品品牌为单选：近似发音先按 vocab-errors.md 归并到预置品牌，全新品牌直接写业务员口述名字即自动新增选项、无需二次确认），link 写关联记录 id，datetime 写 `YYYY-MM-DD HH:mm:ss`）。
7. 回读验证：写入后通过飞书连接器重新查询该记录，核对客户关联、日期、金额守恒后再回执（建了哪表哪条、照片归档位置、水印日期、存疑字段）。**空记录检查：若一次写入多产生一条主字段为空的记录，立即删除并复核条数。**
8. **自动重算开发阶段（全自动，业务员不手选）**：写完拜访/上样/回单（含每周订单导入）后，统计该客户上样登记条数、回单笔数、「意向产品/需求」是否非空、是否在谈上样报价、最近一次拜访结果，按 references/base-schema.md「开发阶段」规则**从高到低**判目标阶段（≥2笔回单→持续补货；1笔→首单已确定；有上样登记→上样待首单；谈上样报价但无上样→上样待确认；有意向需求→已明确需求；否则初步接触），与当前阶段比较**取较高者（只进不退）**，通过连接器更新客户名单.开发阶段。最近一次拜访结果=明确拒绝且其后无上样/回单→置「明确拒绝」；之后再出现上样/回单则复活推进。新建客户初始=初步接触。**重算阶段后，若业务员本次没给具体下次跟进日期且阶段≠明确拒绝，按阶段默认间隔经连接器更新客户名单.下次跟进日期=录入日+N天（初步接触+3；已明确需求/上样待确认/上样待首单+7；首单已确定/持续补货+10）；业务员给了具体日期则以其为准、不覆盖；明确拒绝留空。**
9. 生成工作群汇报文案：按 references/entry-template.md 的「工作群汇报文案」模板，生成可直接复制发群的文字；无内容板块自动省略，数字、型号与录入一致。

## 结构对账与自动升级（旧副本无需重新复制）

- **触发时机**：安装确认 Base 后；技能更新版本后、本对话第一次写入前；使用者要求检查时。
- **做法**：通过飞书连接器，以 references/base-schema.md（结构 SSOT，末尾 Changelog）为准，按**名字**比对该副本实际的表 / 字段 / 视图 / 看板组件——缺表建表、缺字段按类型建、select 缺选项追加、缺视图补视图并配筛选排序、缺看板组件补建；**只增不删、不清空数据**，含数据的列先读旧值再安全转换，串行间隔 2–3 秒防限流，回读核对后回执。
- **不写死母版 id**：各副本 id 不同，以该副本实际 id 与字段名为准，公式按 base-schema 表达式原样建；权限受限等无法自动完成的项列入回执、说明缺口。

## 每周订单数据导入（每周一次）

使用者每周把销售/订单明细（Excel/CSV/截图）发来，自动识别后写入**回单记录**，须含：订单日期、客户名、产品、数量、单价、总金额。完整教程见 references/import-guide.md。Excel 文件可直接拖入 WorkBuddy 或通过连接器读取。

## 上样照片登记（特殊流程）

- 发照片 + 公司名：先读照片，识别**水印相机时间**（年月日时分），写入「上样日期」（不默认今天；水印看不清先问）。
- 照片归档：门头签单合照 / 协议合照 / 上样前照片 / 上样后照片四个附件字段，按说明分类，拿不准问；通过飞书连接器的附件/文件上传能力写入。
- **必传校验（用户确认 B）**：门头签单合照、上样后照片必传且须水印相机照片，缺任一张当场追问补齐才提交；协议合照、上样前有则传、无则不阻断。**同一客户同一时间段多张照片合并为同一条上样记录**，按内容分到四个照片字段，不重复建档。
- 老客户自动挂「关联客户」；新客户先建档。

## 工具调用（通过飞书连接器，非命令行）

- 查表/字段、查客户：调用飞书连接器的多维表格「查询表/字段、查询记录」工具。
- 新建/更新记录：调用连接器的「新建记录 / 更新记录」工具。
- 附件：调用连接器的「上传附件/文件」能力。
- 写后必须重新查询回读，禁止仅凭写入成功宣称完成。

## 铁律

- 首次录入前必须确认录入人姓名；不同 WorkBuddy 对话各自确认。
- 数字（金额、价格、采购量、电话）必须回读复核，语音听错概率高。
- 上样日期一律以照片水印时间为准，除非使用者明确"以我说的为准"。
- 只写存储字段；auto_number / formula / created_at 等只读字段不写。
